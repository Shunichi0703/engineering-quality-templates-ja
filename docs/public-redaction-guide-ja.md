# 公開時マスキングガイド

## 目的

実務文書を公開用の例や知識共有資料へ変換するときに、識別情報、個人情報、
機密情報が本文や履歴へ残ることを防ぎます。単に文字を黒塗りするのではなく、
公開ファイルから情報そのものを除去してください。

## 公開してはいけない情報

- 実在する会社名、顧客名、仕入先名、ブランド名
- 氏名、連絡先、アカウント、署名などの個人情報
- 図面番号、部品番号、車両 ID、製造番号、設備識別番号
- 契約、係争、法的評価などの法務情報
- 健康、診断、受診などの健康情報
- 履歴書、職歴、評価などのキャリア情報
- 価格、原価、数量、能力、未公開計画、認証情報、秘密鍵
- 公開権限を確認できない画像、表、引用、添付ファイル

## 安全な置き換え例

| 元の情報の種類 | 公開用の表現 |
| --- | --- |
| 組織名 | 組織A、依頼元、回答側 |
| 製品・部品名 | 汎用ブラケット、対象部品 |
| 図面・仕様 | 資料A、関連仕様 |
| 人名 | 設計担当の役割、承認者の役割 |
| 日時 | 架空の日付または相対的な期間 |
| 数値 | 技術的意味を損なわない架空値または範囲 |

伏字の一部から元の情報を推測できる場合は、分類名へ置き換えます。
識別子の桁数や接頭辞も残さないでください。

## 本文以外の確認

### 画像と添付ファイル

- 画像内の銘板、顔、画面、位置情報、識別ラベルを除去する
- トリミング外に元画像の情報が残っていないか確認する
- PDF、表計算、プレゼンテーションのコメントと非表示要素を確認する
- ファイルの作成者、位置情報、端末名などのメタデータを削除する

### リンクと参照

- 社内 URL、共有リンク、問い合わせ先を削除する
- リンク先の閲覧権限ではなく、公開可能性そのものを確認する
- ファイル名、アンカー名、代替テキストにも識別情報がないか確認する

### Git 履歴

現在のファイルから削除しても、過去のコミットには情報が残ります。
公開前にコミット履歴、差分、ブランチ、タグを確認してください。
機密情報を含む履歴を公開してはいけません。履歴除去に確信が持てない場合は、
確認済みのファイルだけで新しいリポジトリを作成します。

## 公開前チェックリスト

- [ ] 公開目的に不要な情報をすべて削除した
- [ ] 禁止情報を全文検索し、検索結果を目視確認した
- [ ] 数値や組合せから元の対象を推測できない
- [ ] 画像、添付、リンク、コメント、メタデータを確認した
- [ ] Git の全履歴、ブランチ、タグを確認した
- [ ] 別の確認者が公開用ファイルだけをレビューした
- [ ] 公開後に誰でも取得・複製できることを理解している

## 誤って公開した場合

1. 公開を停止し、対象リポジトリまたはファイルへのアクセスを制限する。
2. 認証情報が含まれた場合は、履歴修正より先に無効化・再発行する。
3. 公開範囲、期間、複製可能性を記録し、定められた連絡経路へ報告する。
4. 現行ファイルだけでなく、履歴、キャッシュ、派生物も確認する。
5. 原因となった公開手順を見直し、確認項目と承認方法を更新する。

情報が取得されていないと推定して、対応を省略しないでください。
