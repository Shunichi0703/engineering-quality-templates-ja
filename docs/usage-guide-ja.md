# 使用ガイド

## 1. テンプレートを選ぶ

- 問題を封じ込め、部門横断で再発防止まで管理する: 8D
- 一つの問題の因果関係を深掘りする: RCA・5Why
- 機械設計の成立性と検証計画を確認する: 設計レビュー
- 相手へ技術条件を確認する: 技術質問票
- 車両への変更影響を確認する: 車両改造チェック
- 複数文書や記載内容の矛盾を確認する: 文書整合性チェック

必要な場合は複数のテンプレートを組み合わせます。例えば、8D の D4 で
5Why を使用し、D7 で設計レビュー項目の更新を確認できます。

## 2. 複製して範囲を定める

原本を直接編集せず、作業用に複製します。最初に目的、対象範囲、対象外、
完了条件を記載します。実在する識別情報をファイル名へ含めないでください。

## 3. 事実と推定を分ける

- 事実には、測定、記録、試験、観察などの根拠を付ける
- 推定には、確認方法と判定基準を付ける
- 不明な情報は空欄にせず、「未確認」と次の行動を記載する
- 個人の注意不足を根本原因とせず、仕組み上の条件を確認する

## 4. レビューする

設計、品質、製造、運用など必要な役割でレビューします。個人名ではなく、
役割、判断内容、根拠、残留リスクを残します。異論がある場合は、結論を急がず、
追加確認の方法と完了条件を合意します。

## 5. 完了を判定する

チェック欄を埋めただけでは完了ではありません。次を確認します。

- 対策が根本原因または流出原因に対応している
- 効果確認の方法、期間、判定基準が明確である
- 暫定処置の解除条件を満たしている
- 残留リスクと管理方法が承認されている
- 関連文書、レビュー、教育、検査へ横展開されている

## 6. 保存・共有する

確定版と作業中の版を区別し、変更理由が追跡できる状態で保存します。
外部共有または公開の前には、
[公開時マスキングガイド](public-redaction-guide-ja.md) を使用してください。
